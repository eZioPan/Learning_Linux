= 进阶材料：证书

== 何时证书是有效的？

证书是由被签名链接在一起的组件构成的。

一个证书可以作为一个整体有效或无效化。但是，即便一个证书是有效的，其中独立的组件（子密钥或身份认证）也可以是无效的。

在本章节中，我们将讨论证书和其组件的有效性。本讨论与签名的有效性紧密关联，并建立在后者之上。

关联一个证书的签名的自身的有效性是必须的预备条件。有两个概念紧密关系到证书和组件的有效性：

* 过期
* 吊销

=== 过期

证书和组件是可以“过期的”，过期会导致它们无效化。证书了每个组件都可以有一个过期时间，或者也可以在时间有效性上保持永久有效。

发送方的 OpenPGP 软件会拒绝使用过期的证书加密电邮，也会拒绝使用过期的加密用组件密钥。发件人的软件会拒绝使用加密密钥，这主要是出于对证书所有者的礼貌，尊重他们在证书元数据中表达的偏好。

OpenPGP 中的过期机制，具有一个扩展/更新过期时间的机制作为补充。

使用过期机制有两个有用的理由：

* 一个过期的证书意味着该证书不可以继续使用。它强制让使用该证书的用户（或它们的 OpenPGP 软件）拉取该证书的更新。比如，从一个密钥服务器拉取更新。
* 这是一种被动的让证书“无效”的方法，比如，当它们的所有者无法再控制它们，或者因为任何原因无法广播一个吊销的时候。

组件密钥使用__密钥过期时间__子包来表达过期时间。身份组件依赖其绑定签名的__签名过期时间__子包。若绑定签名过期，则绑定无效化，而组件也被认为是过期了。
