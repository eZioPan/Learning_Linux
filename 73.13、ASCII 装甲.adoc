= ASCII 装甲

OpenPGP 数据的原生格式为二进制。

但是，在很多情况下，它经常以名为“ASCII 装甲（ASCII armor）”的非二进制编码格式出现。举例来说，ASCII 装甲后的 OpenPGP 数据——比如加密后信息和签名——常用于电邮中。

== 机制

OpenPGP 的 ASCII 装甲机制包括：

* 一个装甲头行（armor header line）
* 可选的数个装甲头，可以包含额外的元数据
*  base64 编码的 OpenPGP 数据
* 一个可选的该数据的校验和（特别的，该行以等号 `=` 开头）
* 一个匹配头行的装甲尾行（armor tail line）（或者叫 footer）

=== 与二进制 OpenPGP 数据的不同

自然，二进制文件并不方便拷贝至电邮的文本信息或类似形式中。但是，二进制是更紧凑的格式。

二进制格式和 ASCII 装甲格式编码了完全相同的信息。所使用的格式会基于 OpenPGP 数据所使用的上下文而不同。

== 明文签名框架

OpenPGP 中有一个值得注意的机制，它使用了 ASCII 装甲的一种特殊变体，即__明文签名框架__，它将 ASCII 加密签名和明文信息存储为一个组合文本文件。

参考 xref:73.07、对数据上签名.adoc#明文签名[明文签名] 章节了解该格式的一个例子

== 进阶话题

=== 可选的校验和和其弃用

历史上，OpenPGP 的 ASCII 装甲机制定义了一个（可选的）为 base64 编码的数据设计的校验和机制。

OpenPGP 第 6 版的规范弃用了该机制。

现有的 CRC24 行尾应该被忽略，而生成这类行尾是强烈不推荐的，除出于非必要兼容性考虑。
