= 进阶材料：加密

== 用证书中的单个/多个子密钥进行加密？

一个接收者的证书可能包含多个可用于加密的子密钥。这引发了一个问题，那就是信息应该用每一个加密用子密钥进行加密么？

有一种观点认为，一个强力的攻击者可能已经向受害者证书中添加了一个，攻击者控制的加密子密钥。此时，仅使用“最新的”加密子密钥就可能揭露这类攻击。但是，一个强力的攻击者也可能仅中间人攻击（MitM）任何发送的信息，仅向受害者控制的加密密钥中添加一个 PKESK，来隐藏发送者使用了不同的密钥的事实。

另一边，一个用户可能有意使用多个加密子密钥。想象一个例子，一个证书在多个设备上使用，但每个设备都有一个独立的加密子密钥，让单一设备遗失导致的吊销更加顺滑。在这种情况下，发送者使用所有可用的加密子密钥进行加密就是很重要的。

== 基于接收者的偏好子包“协商”算法

=== 防止“降级” -> 策略

当讨论密钥长度和算法的时候，每个实现应该定义一个“最小”的安全级别。若一组接收者的对称密钥算法偏好的最小公因数的安全性太差，那么实现要么应该回退至配置回退用算法，要么就直接不生成报文。
